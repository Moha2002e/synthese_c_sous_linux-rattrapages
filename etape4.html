📋 SYNTHÈSE COMPLÈTE - ÉTAPE 4

ACCÈS UNIQUE À LA BASE DE DONNÉES ET CRÉATION D'UN PIPE

🎯 Objectif de cette étape

Cette étape optimise l'architecture en centralisant l'accès à la base de données via un processus unique AccesBD. Cela évite les connexions multiples et les accès concurrents qui pourraient rendre les stocks inconsistants.

```cpp // Serveur - Création pipe if(pipe(fdPipe) == -1) { perror("(SERVEUR) échec de création du pipe\n"); exit(1); } // Serveur - Création AccesBD avec descripteur lecture sprintf(buffer,"%d", fdPipe[0]); procAccesBd = creerProcessusFils(2,"./AccesBD", "AccesBD", buffer ,NULL); // Serveur - Création Caddie avec descripteur écriture sprintf(buffer, "%d", fdPipe[1]); tab->connexions[i].pidCaddie = creerProcessusFils(2,"./Caddie", "Caddie", buffer,NULL); ```

2. Création du processus AccesBD

```cpp // AccesBD - Lecture pipe et traitement while(1) { int lecture = read(fdRpipe, &m, sizeof(MESSAGE)); if (lecture == 0) { // Fin de communication mysql_close(connexion); exit(1); } case CONSULT: aEnvoyer = requeteSqlArticle(m.data1); // Préparation réponse reponse.type = m.expediteur; // PID du Caddie reponse.expediteur = getpid(); reponse.requete = CONSULT; if (aEnvoyer.stock == -1) { reponse.data1 = -1; // Article non trouvé } else { // Remplissage données article reponse.data1 = aEnvoyer.id; strcpy(reponse.data2, aEnvoyer.intitule); // ... } msgsnd(idQ, &reponse, sizeof(MESSAGE) - sizeof(long), 0); } ```

3. Passage du descripteur pipe au Caddie lors du login

```cpp // Serveur - Création Caddie avec descripteur écriture sprintf(buffer, "%d", fdPipe[1]); tab->connexions[i].pidCaddie = creerProcessusFils(2,"./Caddie", "Caddie", buffer,NULL); ```

4. Processus Caddie - Communication via pipe

```cpp // Caddie - Envoi via pipe void wPipe(MESSAGE* pM) { pM->expediteur = getpid(); // Remplace par PID Caddie write(fdWpipe, pM, sizeof(MESSAGE)); // Envoi vers AccesBD msgrcv(idQ,pM,sizeof(MESSAGE)-sizeof(long),getpid(),0); // Attente réponse } ```

5. Processus AccesBD - Gestion des requêtes

```cpp // AccesBD - Lecture pipe et traitement while(1) { int lecture = read(fdRpipe, &m, sizeof(MESSAGE)); if (lecture == 0) { // Fin de communication mysql_close(connexion); exit(1); } // ... traitement des requêtes ... } ```

📈 PARCOURS UTILISATEUR COMPLET

1. Démarrage du système

  • Serveur démarre
  • Création pipe (fdPipe[0], fdPipe[1])
  • Lancement processus AccesBD avec fdPipe[0]
  • AccesBD se connecte à MySQL
  • AccesBD entre en boucle de lecture pipe

2. Connexion d'un client

  • Client se connecte et s'authentifie
  • Serveur crée processus Caddie avec fdPipe[1]
  • Caddie récupère descripteur écriture
  • Caddie n'a plus de connexion MySQL
  • Client envoie CONSULT(1)

3. Consultation d'article

  • Serveur transfère CONSULT vers Caddie
  • Caddie modifie expediteur = getpid()
  • Caddie écrit message sur pipe
  • AccesBD lit message du pipe
  • AccesBD interroge MySQL
  • AccesBD envoie réponse via file de messages
  • Caddie reçoit réponse et la transmet au client

4. Fermeture du système

  • CTRL-C sur serveur
  • Serveur ferme pipe (fdPipe[0], fdPipe[1])
  • AccesBD détecte fin communication (read() = 0)
  • AccesBD ferme connexion MySQL et exit
  • Caddies échouent sur write() et exit
  • Nettoyage complet des ressources

🎯 SYNTHÈSE FINALE

Cette étape optimise l'architecture en centralisant l'accès à la base de données avec :

  • Accès unique à MySQL : Un seul processus AccesBD
  • Communication via pipe : Transfert efficace des requêtes
  • Évitement des accès concurrents : Pas de conflits sur les stocks
  • Gestion robuste des erreurs : Détection fin de communication
  • Architecture scalable : Support de multiples clients
  • Nettoyage propre : Fermeture automatique des ressources

Le système garantit maintenant une cohérence des données et une performance optimisée en évitant les connexions multiples à la base de données.

Avantages de cette architecture :
- Cohérence : Accès sérialisé à la base de données
- Performance : Réduction du nombre de connexions MySQL
- Robustesse : Gestion centralisée des erreurs
- Scalabilité : Support de nombreux clients simultanés
- Maintenabilité : Logique d'accès BD centralisée
